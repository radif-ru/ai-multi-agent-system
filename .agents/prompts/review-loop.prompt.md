# Промпт: цикл «ревью → доработка» до чистого прохода

Проведи итеративную доработку изменений: ревью, исправление замечаний, повторное ревью — пока не останется блокирующих замечаний. Я передаю diff (или ветку/список изменённых файлов) и, при необходимости, цель изменений.

Правила цикла:

1. **Ревью.** Проверь diff по чек-листу проекта (`code-review.prompt.md`, скилл `pr-review-discipline`): хирургичность, минимализм, тесты, async, ошибки, безопасность, документация, язык.
2. **Сортировка замечаний.** Раздели найденное на три группы:
   - **чинить сейчас** — корректность, безопасность, отсутствие тестов на новое поведение, нарушение контрактов проекта;
   - **опционально** — стиль, читаемость, некритичные улучшения;
   - **отклонить** — с кратким обоснованием (вкусовщина, вне scope, ломает минимализм).
3. **Доработка.** Примени только группу «чинить сейчас» минимальными правками. Не применяй слепо каждое замечание — сверяй с `AGENTS.md` §2–§3.
4. **Проверка.** `pytest -q` и `flake8` зелёные после каждой итерации.
5. **Повтор.** Проведи ревью исправленного diff заново. Нет замечаний «чинить сейчас» — цикл завершён.
6. **Лимит — 3 итерации.** Замечания не сходятся — остановись и вынеси спорные пункты мне пронумерованным списком с вариантами решения.

Формат итога: вердикт (чисто / остались риски), список применённых исправлений, отклонённые замечания с обоснованием, опциональные улучшения — отдельным списком без применения (если я явно не попросил применить и их).
