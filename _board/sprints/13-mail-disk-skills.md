## 1. Цель спринта

Дать боту практическую ценность для повседневных задач: чтение и разбор почты (Яндекс, Gmail) и файлов Яндекс.Диска прямо из чата (Telegram / консоль / MAX), с человекочитаемыми предупреждениями при неподключённой или некорректной конфигурации. Параллельно расширить контракт скиллов исполняемыми скриптами (`scripts/` + sandbox-tool `run_skill_script`) и пополнить библиотеку скиллов практическими инструкциями.

Вторая цель — принять взвешенные архитектурные решения по трём направлениям (RLM-подход к длинным контекстам, n8n, разделение на микросервисы) через spike-исследования с фиксацией решений, не раздувая кодовую базу преждевременно.

## 2. Скоуп и non-goals

### В скоупе

- Почта: read-only доступ по IMAP (Яндекс, Gmail; пароли приложений) — список, чтение, поиск писем.
- Яндекс.Диск: read-only доступ по REST API (OAuth-токен) — список файлов, скачивание в каталог пользователя.
- Предупреждения о неподключённой/некорректной конфигурации во всех каналах (через observation агентного цикла).
- Скиллы со скриптами: расширение `SkillRegistry`, tool `run_skill_script` (sandbox: таймаут, только скрипты из репозитория, allowlist).
- Новые скиллы: `email-assistant` (разбор почты), `humanizer` (очеловечивание текста), `code-review` (обзор кода) — частично закрывают roadmap Этап 8.
- Spikes: RLM-подход, n8n, микросервисы → документы-решения + записи в roadmap.
- Процесс: тип задачи spike в `_board/process.md`; актуализация `README.md` и документации.

### Вне скоупа (non-goals)

- Отправка, удаление, маркировка писем; создание черновиков (→ roadmap).
- OAuth-flow Gmail API / Яндекс 360 API (используем IMAP + пароли приложений).
- Запись на Яндекс.Диск, upload файлов (→ roadmap).
- Реализация RLM-аналога, n8n-интеграции, разреза на сервисы (только spikes).
- Google Диск (не запрашивался).
- Скрипты, генерируемые агентом на лету (`run_skill_script` исполняет только скрипты из репозитория).
